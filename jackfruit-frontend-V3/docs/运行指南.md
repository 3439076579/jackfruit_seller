# 运行指南

两条路，按需要选。

| | 方案 A：Mock 模式 | 方案 B：真实后端 |
| --- | --- | --- |
| 前置条件 | 只要 Node 18+ | Node 18+ **和** Go **和** MySQL |
| 准备耗时 | 2 分钟 | 1–2 小时（含下载安装） |
| 数据 | 内置内存数据，重启即重置 | 真实 MySQL 数据，可持久化 |
| 适合 | 看界面、调样式、写页面、日常开发 | 答辩演示真实链路、验证接口 |
| 风险 | 改数据的操作重启后丢失 | 装环境可能踩坑 |

**建议顺序：先用 A 把界面跑起来、把页面写完，最后要演示真实链路时再上 B。** 前端代码在两种模式下完全一样，切换只改一个环境变量。

---

## 方案 A：Mock 模式（推荐起步）

### 步骤

```bash
cd jackfruit-frontend-V3
npm install        # 首次约 2–3 分钟
npm run dev
```

打开 http://localhost:5173 ，会自动跳到登录页。

> 若 5173 已被别的程序占用，Vite 会自动换到 5174 并在终端提示 `Port 5173 is in use`。
> **始终以终端打印的 `Local:` 地址为准**，不要死记 5173。

终端出现这行说明 Mock 已生效：

```
[mock] 已启用内存 Mock 接口（数据随 dev server 重启重置）
```

### 可用账号

| 用户名 | 密码 | 角色 | 说明 |
| --- | --- | --- | --- |
| `admin` | `123456` | 管理员 | 登录后进后台，有 1 条历史订单、1 条评价 |
| `omnis` | `123456` | 普通会员 | 登录后进商城，有 1 条历史订单、2 条评价 |
| `user01` | `123456` | 普通会员 | 手机号与邮箱未填，可用来看「未填写」展示 |

注册页也能用，新账号默认是普通会员。

角色由 `src/config/permissions.ts` 里的用户名白名单决定。**后端没有角色字段**，
所以这是界面层的可见性控制，不是安全边界 —— 详见 README 的「账户与权限」一节。

### 演示路径

推荐按这条线走，能完整体现业务流程：

1. **登录页** → 用 `admin` / `123456` 登录，观察表单校验（用户名超 20 字符会被拦）
2. **每日推荐** → 5 个商品卡片，含图片、分类标签、价格、库存状态
3. **点「详情」** → 商品描述 + 评价列表（`特级红肉波罗蜜` 有 2 条评价）
4. **点「购买」** → 填地址和数量 → 提交订单，**库存立即减少**
5. 顶部菜单进 **我的订单**，能看到刚下的单
6. 地址栏改 `/admin/dashboard` → 后台首页：指标卡、销量 TOP5、分类销售额、最新公告
7. **波罗蜜管理** → 新增商品（必须选一张图片）、编辑、删除、分类管理
8. **订单管理** → 订单号搜索与分页；**统计分析** → 销量排行、高分商品筛选
9. 顶栏头像菜单 → **发布公告**，回到商城首页会弹出这条公告
10. **角色对比**：退出后用 `user01` / `123456` 登录 →
    落到商城首页而非后台，顶栏没有「后台管理」入口，
    地址栏手动输入 `/admin/dashboard` 会被弹回商城并提示无权限

终端里每个请求都会打印一行 `[mock] ok POST /user/login success`，可用来讲请求链路。

### Mock 覆盖范围

已实现全部 20 个后端接口，业务规则尽量照抄后端，包括它的怪癖：

- 商品更新时 `storage = 0` / `price = 0` 视为「不修改」
- 订单返回的 `user` 字段是全零对象（后端只 Preload 了 `Jackfruit`），前端 adapters 会把它转成 `null`
- 重复评价同一商品会被拒

未覆盖的部分：

- 上传的图片文件不落盘，新增商品固定返回一张占位图
- 数据只存在内存，`npm run dev` 重启后回到初始状态

### 切回真实后端

改 `.env.development` 一行：

```diff
- VITE_USE_MOCK=true
+ VITE_USE_MOCK=false
```

重启 `npm run dev`。此时 Vite 改为把 `/api/*` 转发到 `localhost:8082`（走方案 B 的后端）。

## 方案 B：真实后端

需要三样东西：Go、MySQL、后端源码（已有，在 `software_project_design/`）。

### B1. 安装 Go

**版本要求**：项目 `go.mod` 声明 `go 1.19`，任何更新的版本都能编译（Go 向后兼容）。推荐当前稳定版 **1.27.4**。

1. 下载安装包（二选一，国内优先镜像）：

| 来源 | 链接 |
| --- | --- |
| 官方下载页 | https://go.dev/dl/ |
| 官方中国镜像 | https://golang.google.cn/dl/ |
| 阿里云镜像（最快） | https://mirrors.aliyun.com/golang/go1.27.4.windows-amd64.msi |

文件名 `go1.27.4.windows-amd64.msi`，约 63MB。

2. 双击一路 Next，默认装到 `C:\Program Files\Go`
3. **关掉所有终端窗口再重开**（PATH 需要刷新）
4. 验证：

```bash
go version
# 应输出 go version go1.27.4 windows/amd64
```

5. **国内必做**：设置模块代理，否则 `go run` 拉依赖会卡住

```bash
go env -w GOPROXY=https://goproxy.cn,direct
```

> 说明：`go.sum` 里有 `bytedance/sonic v1.9.1`（Gin 的 JSON 加速库），但 Gin 1.9.1 需要显式 `-tags=sonic` 才会编译它，默认走 `encoding/json`，所以不会因为 Go 版本新而编译失败。

### B2. 安装 MySQL

**版本选择**：**8.4 LTS**（`8.4.13`）。不要选下载首页默认显示的 `26.10`——那是 Innovation 版，每季度淘汰，只适合尝鲜。

| 版本 | 状态 | 建议 |
| --- | --- | --- |
| 8.4 LTS | 支持到 2032 | **推荐**，与项目驱动 `go-sql-driver/mysql v1.7.1` 匹配最稳 |
| 9.7 LTS | 支持到 2034 | 也可用，但移除了 `mysql_native_password`，老客户端可能连不上 |
| 8.0 | 2026-04 已 EOL | 不推荐，仅当 8.4 装不上时兜底 |
| 26.x / 9.0–9.6 | Innovation | 不要用 |

**注意：8.4 不能用 MySQL Installer 装。** 官方已明确「8.0 是最后一个带 Installer 的系列」，8.1 起改为 MSI 安装，但 MSI 自带 **MySQL Configurator** 图形配置向导，步骤同样简单。

1. 下载 MSI：

| 来源 | 链接 |
| --- | --- |
| 8.4 下载页 | https://dev.mysql.com/downloads/mysql/8.4.html |
| 直链（129.9MB） | https://dev.mysql.com/get/Downloads/MySQL-8.4/mysql-8.4.13-winx64.msi |

页面底部点 **No thanks, just start my download** 即可，无需登录。

2. 双击 `mysql-8.4.13-winx64.msi`，一路 Next 装完（默认 `C:\Program Files\MySQL\MySQL Server 8.4`）
3. 装完会自动弹出 **MySQL Configurator**；没弹出就从开始菜单搜 `MySQL Configurator` 打开
4. Configurator 里一路 Next，只在两处停下来：
   - **Type and Networking**：保持默认端口 `3306`、`Config Type = Development Computer`
   - **Accounts and Roles**：设置 **root 密码** —— 记下来，B4 要用
5. 最后一步点 **Execute**，等所有项变绿，点 Finish
6. 验证（新开一个终端）：

```bash
"C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql" -u root -p
# 输入刚才的密码，出现 mysql> 提示符就成功了
```

> 如果 `mysql` 命令找不到，说明 bin 目录没进 PATH。可以手动加：系统属性 → 环境变量 → Path → 新建 `C:\Program Files\MySQL\MySQL Server 8.4\bin`，然后重开终端。

### B3. 建库

```sql
mysql -u root -p
```

```sql
CREATE DATABASE sf_project CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
EXIT;
```

### B4. 配置后端数据库连接

后端通过环境变量 `DB_DSN` 读取数据库连接串，**不设会用源码里的默认密码，必然连不上**。

**启动前必须设置环境变量**：

```cmd
cd /d "D:\03_港城莞\课程资源\GroupWork\5003\波罗蜜\software_project_design"
set "DB_DSN=root:你的密码@tcp(localhost:3306)/sf_project?charset=utf8&parseTime=True&loc=Local"
go run main.go
```

成功的标志是这两行**同时**出现：

```json
{"level":"info","msg":"MySQL DSN source","source":"env:DB_DSN"}
[GIN-debug] Listening and serving HTTP on localhost:8082
```

如果 `source` 显示 `built-in default`，说明 `DB_DSN` 没传进去，接下来必然 `Access denied` —— 检查环境变量是否设置成功。

验证：

```bash
curl http://localhost:8082/jackfruit/list
# 应返回 {"status_code":0,"data":[],"message":"success"}
```

空数组是正常的 —— 数据库刚建好，还没有商品。

### B5. 造一批初始数据

后端不带种子数据。仓库里已经准备好了脚本 `software_project_design/seed.sql`，内容与 Mock 模式完全对齐：3 个用户、3 个分类、5 个商品、3 个订单、3 条评价、1 条公告。

**导入方式**（命令行）：

```cmd
cd /d "D:\03_港城莞\课程资源\GroupWork\5003\波罗蜜\software_project_design"
"C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe" -u root -p --default-character-set=utf8mb4 sf_project < seed.sql
```

按提示输入 MySQL root 密码。

脚本末尾会打印各表行数，正常应该长这样：

```
user       3
category   3
jackfruit  5
orders     3
review     3
notify     1
```

脚本可以重复执行：用户/分类/评价靠唯一索引去重，商品/订单/公告只在表为空时插入，不会翻倍。

> **列名容易踩的坑**：GORM 按 Go 字段名转下划线，和 JSON tag 不是一回事。
>
> | JSON 里看到的 | 数据库真实列名 |
> | --- | --- |
> | `name` | `product_name` |
> | `feature` | `jackfruit_feature` |
> | `address` | `user_address` |
> | `total` | `total_cost` |
>
> 手动写 SQL 时用错会报 `Unknown column`。用 `seed.sql` 就不用管这些。

导入完验证接口：

```bash
curl http://localhost:8082/jackfruit/list
# 应返回 5 条商品
```

### B6. 把前端切到真实模式

```diff
# .env.development
- VITE_USE_MOCK=true
+ VITE_USE_MOCK=false
```

重启 `npm run dev`。现在前端真的在读写 MySQL 了 —— 下单会扣库存，重启浏览器数据还在。

### 排错表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `go: command not found` | 装完没重开终端 | 关掉所有终端重开 |
| `go run` 卡在 `downloading` | 没设 GOPROXY | 执行 B1 第 5 步 |
| `Access denied for user 'root'` | 密码错，或 `DB_DSN` 没生效 | 看日志里 `MySQL DSN source` 是不是 `env:DB_DSN`；不是就检查环境变量是否设置成功 |
| `Unknown database 'sf_project'` | 没建库 | 回到 B3 |
| `connect: connection refused`（3306） | MySQL 服务没启动 | `net start MySQL84`（管理员终端），或在服务管理器里启动 |
| `mysql` 命令找不到 | bin 目录不在 PATH | 用完整路径 `"C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql" -u root -p`，或按 B2 手动加 PATH |
| Configurator 里点完 Next 就关了，服务没注册 | 漏了最后的 **Execute** | 重开 MySQL Configurator，走完后点 Execute 等全绿 |
| `this authentication plugin is not supported` | 用了 9.7 且客户端太老 | 换 8.4 LTS，或升级驱动 `go get github.com/go-sql-driver/mysql@v1.8.1` |
| 前端登录提示 `record not found` | 库里没用户 | 执行 B5 的导入 |
| 前端请求全部 404 | 忘了切 `VITE_USE_MOCK=false` | 改环境变量并重启 dev |
| 商品图片裂开 | image 字段不是 `http://localhost:8082/static/...` | 按 B5 重新导入数据 |
| 时间显示 `0001-01-01` | DSN 少了 `parseTime=True` | 检查 B4 的连接串 |

## 为什么 Mock 不算「假前端」

这是这套方案跟临时贴图最大的区别：

1. **Mock 返回的是后端 raw 契约**（`ID` 大写、`category_name` 下划线、`Message` 首字母大写），不是前端模型。所以 `src/adapters/` 这一层在 Mock 下被真实走了一遍。
2. **类型上有约束**：`mock/data.ts` 直接 `import type` 了 `src/types/raw.ts`，字段名一旦和后端契约不一致就编译不过。
3. **规则照抄后端**：库存扣减、重复评价拦截、零值视为不修改，这些行为都复刻了。

结果就是：Mock 下跑通的页面，切到真实后端不会因为字段名或返回结构而崩。唯一会变的是「数据从哪来」。

如果想自己验证这层约束，跑一下这条命令：

```bash
npm run type-check        # 前端源码
npx tsc -p tsconfig.node.json --noEmit   # mock 与 vite 配置
```
