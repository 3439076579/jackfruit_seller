# 运行指南

两条路，按需要选。

| | 方案 A：Mock 模式 | 方案 B：真实后端 |
| --- | --- | --- |
| 前置条件 | 只要 Node 18+ | Node 18+ **和** Go **和** MySQL |
| 准备耗时 | 2 分钟 | 1–2 小时（含下载安装） |
| 数据 | 内置内存数据，重启即重置 | 真实 MySQL 数据，可持久化 |
| 适合 | 看界面、调样式、写页面、日常开发 | 答辩演示真实链路、验证接口 |
| 风险 | 改数据的操作重启后丢失 | 装环境可能踩坑 |

**建议顺序：先用 A 把界面跑起来、把页面写完，最后要演示真实链路时再上 B。** 前端代码在两种模式下完全一样，切换只改一个环境变量。

---

## 方案 A：Mock 模式（推荐起步）

### 步骤

```bash
cd jackfruit-frontend-V3
npm install        # 首次约 2–3 分钟
npm run dev
```

打开 http://localhost:5173 ，会自动跳到登录页。

> 若 5173 已被别的程序占用，Vite 会自动换到 5174 并在终端提示 `Port 5173 is in use`。
> **始终以终端打印的 `Local:` 地址为准**，不要死记 5173。

终端出现这行说明 Mock 已生效：

```
[mock] 已启用内存 Mock 接口（数据随 dev server 重启重置）
```

### 可用账号

| 用户名 | 密码 | 角色 | 说明 |
| --- | --- | --- | --- |
| `admin` | `123456` | 管理员 | 登录后进后台，有 1 条历史订单、1 条评价 |
| `omnis` | `123456` | 普通会员 | 登录后进商城，有 1 条历史订单、2 条评价 |
| `user01` | `123456` | 普通会员 | 手机号与邮箱未填，可用来看「未填写」展示 |

注册页也能用，新账号默认是普通会员。

角色由 `src/config/permissions.ts` 里的用户名白名单决定。**后端没有角色字段**，
所以这是界面层的可见性控制，不是安全边界 —— 详见 README 的「账户与权限」一节。

### 演示路径

推荐按这条线走，能完整体现业务流程：

1. **登录页** → 用 `admin` / `123456` 登录，观察表单校验（用户名超 20 字符会被拦）
2. **每日推荐** → 5 个商品卡片，含图片、分类标签、价格、库存状态
3. **点「详情」** → 商品描述 + 评价列表（`特级红肉波罗蜜` 有 2 条评价）
4. **点「购买」** → 填地址和数量 → 提交订单，**库存立即减少**
5. 顶部菜单进 **我的订单**，能看到刚下的单
6. 地址栏改 `/admin/dashboard` → 后台首页：指标卡、销量 TOP5、分类销售额、最新公告
7. **波罗蜜管理** → 新增商品（必须选一张图片）、编辑、删除、分类管理
8. **订单管理** → 订单号搜索与分页；**统计分析** → 销量排行、高分商品筛选
9. 顶栏头像菜单 → **发布公告**，回到商城首页会弹出这条公告
10. **角色对比**：退出后用 `user01` / `123456` 登录 →
    落到商城首页而非后台，顶栏没有「后台管理」入口，
    地址栏手动输入 `/admin/dashboard` 会被弹回商城并提示无权限

终端里每个请求都会打印一行 `[mock] ok POST /user/login success`，可用来讲请求链路。

### Mock 覆盖范围

已实现全部 20 个后端接口，业务规则尽量照抄后端，包括它的怪癖：

- 商品更新时 `storage = 0` / `price = 0` 视为「不修改」
- 订单返回的 `user` 字段是全零对象（后端只 Preload 了 `Jackfruit`），前端 adapters 会把它转成 `null`
- 重复评价同一商品会被拒

未覆盖的部分：

- 上传的图片文件不落盘，新增商品固定返回一张占位图
- 数据只存在内存，`npm run dev` 重启后回到初始状态

### 切回真实后端

改 `.env.development` 一行：

```diff
- VITE_USE_MOCK=true
+ VITE_USE_MOCK=false
```

重启 `npm run dev`。此时 Vite 改为把 `/api/*` 转发到 `localhost:8082`（走方案 B 的后端）。

## 方案 B：真实后端

需要三样东西：Go、MySQL、后端源码（已有，在 `software_project_design/`）。

### B1. 安装 Go

1. 打开 https://go.dev/dl/ ，下载 `go1.22.x.windows-amd64.msi`（比项目要求的 1.19 新，向下兼容）
2. 双击一路 Next，默认装到 `C:\Program Files\Go`
3. **关掉所有终端窗口再重开**（PATH 需要刷新）
4. 验证：

```bash
go version
# 应输出 go version go1.22.x windows/amd64
```

5. **国内必做**：设置模块代理，否则 `go run` 拉依赖会卡住

```bash
go env -w GOPROXY=https://goproxy.cn,direct
```

### B2. 安装 MySQL

推荐用官方 Installer，最省心：

1. 打开 https://dev.mysql.com/downloads/installer/ ，下载 `mysql-installer-community-8.x.msi`
2. 安装类型选 **Custom**，只勾选 **MySQL Server**（Workbench 可选，用不上）
3. 一路 Next，到 **Authentication Method** 时选 `Use Strong Password Encryption`
4. 设置 root 密码 —— **记下来，下一步要用**
5. Windows Service 那步勾选 `Start the MySQL Server at System Startup`，服务名默认 `MySQL80`
6. 完成后验证：

```bash
mysql -u root -p
# 输入刚才的密码，能进 mysql> 提示符就成功了
```

> 如果 `mysql` 命令找不到，说明没加 PATH，用完整路径：
> `"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql" -u root -p`

### B3. 创建数据库

在 `mysql>` 提示符里执行：

```sql
CREATE DATABASE IF NOT EXISTS sf_project
  DEFAULT CHARSET utf8mb4
  COLLATE utf8mb4_general_ci;
```

**表不用手动建** —— 后端启动时 `AutoMigrate` 会自动创建 6 张表。

### B4. 改数据库连接串

后端把 DSN 硬编码在 `software_project_design/global/global.go` 里，必须改成你自己的 root 密码：

```go
// 原来
OpenMySQL("root:wjb20031205@tcp(localhost:3306)/sf_project?charset=utf8&parseTime=True&loc=Local")

// 改成你的密码，例如 123456
OpenMySQL("root:123456@tcp(localhost:3306)/sf_project?charset=utf8&parseTime=True&loc=Local")
```

注意 `charset=utf8&parseTime=True&loc=Local` 这三段不要动，去掉会导致时间字段解析失败。

### B5. 启动后端

```bash
cd software_project_design
go run main.go
```

首次会下载依赖（约 30 秒到 2 分钟）。看到下面这行就成功了：

```
[GIN-debug] Listening and serving HTTP on localhost:8082
```

验证：

```bash
curl http://localhost:8082/jackfruit/list
# 应返回 {"status_code":0,"data":[],"message":"success"}
```

空数组是正常的 —— 数据库刚建好，还没有商品。

### B6. 造一批初始数据

后端没有种子数据，需要手工插入。在 `mysql>` 里执行：

```sql
USE sf_project;

-- 用户（密码明文，后端就是这么比的）
INSERT INTO user (created_at, updated_at, username, password, phone, email) VALUES
  (NOW(), NOW(), 'admin', '123456', '13800000001', 'admin@example.com'),
  (NOW(), NOW(), 'omnis', '123456', '13900000002', 'omnis@example.com');

-- 分类
INSERT INTO category (created_at, updated_at, category_name) VALUES
  (NOW(), NOW(), '特级果'),
  (NOW(), NOW(), '一级果'),
  (NOW(), NOW(), '果肉制品');

-- 商品（图片用后端自带的 data 目录，经 /static/ 直接访问）
INSERT INTO jackfruit
  (created_at, updated_at, category_id, product_name, storage, price, image,
   management_info, jackfruit_feature, plant_intro)
VALUES
  (NOW(), NOW(), 1, '特级红肉波罗蜜', 30, 158,
   'http://localhost:8082/static/jackfruit1.png',
   '恒温 12℃ 存放，避免挤压', '果肉橙红、干包少汁，单果 8-10 斤', '海南万宁产区，8 年老树'),
  (NOW(), NOW(), 2, '一级红肉波罗蜜', 45, 128,
   'http://localhost:8082/static/jackfruit2.png',
   '常温阴凉处存放', '果肉饱满、甜度适中，单果 6-8 斤', '广东湛江产区，施用有机肥'),
  (NOW(), NOW(), 3, '波罗蜜果肉真空装 500g', 120, 45,
   'http://localhost:8082/static/jackfruit3.png',

```

> 列名注意：`product_name` 和 `jackfruit_feature` 是 GORM 按 Go 字段名自动转换的结果，
> 不是 JSON 里的 `name` / `feature`。写错会报 `Unknown column`。

插完刷新后端接口，`/jackfruit/list` 应该返回 3 条。

### B7. 把前端切到真实模式

```diff
# .env.development
- VITE_USE_MOCK=true
+ VITE_USE_MOCK=false
```

重启 `npm run dev`。现在前端真的在读写 MySQL 了 —— 下单会扣库存，重启浏览器数据还在。

### 排错表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `go: command not found` | 装完没重开终端 | 关掉所有终端重开 |
| `go run` 卡在 `downloading` | 没设 GOPROXY | 执行 B1 第 5 步 |
| `Access denied for user 'root'` | 密码没改 | 回到 B4 改 DSN |
| `Unknown database 'sf_project'` | 没建库 | 回到 B3 |
| `connect: connection refused`（3306） | MySQL 服务没启动 | 服务管理器里启动 `MySQL80` |
| 前端登录提示 `record not found` | 库里没用户 | 执行 B6 的 INSERT |
| 前端请求全部 404 | 忘了切 `VITE_USE_MOCK=false` | 改环境变量并重启 dev |
| 商品图片裂开 | image 字段不是 `http://localhost:8082/static/...` | 按 B6 重新插数据 |
| 时间显示 `0001-01-01` | DSN 少了 `parseTime=True` | 检查 B4 |

## 为什么 Mock 不算「假前端」

这是这套方案跟临时贴图最大的区别：

1. **Mock 返回的是后端 raw 契约**（`ID` 大写、`category_name` 下划线、`Message` 首字母大写），不是前端模型。所以 `src/adapters/` 这一层在 Mock 下被真实走了一遍。
2. **类型上有约束**：`mock/data.ts` 直接 `import type` 了 `src/types/raw.ts`，字段名一旦和后端契约不一致就编译不过。
3. **规则照抄后端**：库存扣减、重复评价拦截、零值视为不修改，这些行为都复刻了。

结果就是：Mock 下跑通的页面，切到真实后端不会因为字段名或返回结构而崩。唯一会变的是「数据从哪来」。

如果想自己验证这层约束，跑一下这条命令（临时脚本已随本次提交清理，可按需重建）：

```bash
npm run type-check        # 前端源码
npx tsc -p tsconfig.node.json --noEmit   # mock 与 vite 配置
```
