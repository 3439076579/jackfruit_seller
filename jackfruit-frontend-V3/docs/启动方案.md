## 二、30 秒快速启动（Mock 模式，推荐先这样看效果）

**无需安装 Go / MySQL**，用内置的内存数据，适合快速评审界面和交互。

```bash
cd jackfruit-frontend-V3
npm install        # 首次约 2–3 分钟
npm run dev
```

打开终端打印的地址（默认 http://localhost:5173）。

> 注意：`.env.development` 当前提交的是 `VITE_USE_MOCK=false`（真实后端模式）。要用 Mock，先把它改成 `VITE_USE_MOCK=true` 再 `npm run dev`。

终端出现 `[mock] 已启用内存 Mock 接口` 即生效。

## 三、完整启动（真实后端，答辩用）

要演示「真的连数据库、下单真的扣库存」，需要 Go + MySQL。

### 环境要求

| 软件 | 版本 | 下载 |
| --- | --- | --- |
| Go | 1.27.4（`go.mod` 声明 1.19，向上兼容） | https://go.dev/dl/ |
| MySQL | **8.4 LTS（8.4.13）** | https://dev.mysql.com/downloads/mysql/8.4.html |

> 版本说明：选 **8.4 LTS**（支持到 2032）。不要装下载首页默认的 26.x Innovation 版（每季度淘汰），也不要用已 EOL 的 8.0。注意 8.4 不能用老的 MySQL Installer 装——官方自 8.1 起改为 MSI 安装，装完用自带的 **MySQL Configurator** 向导设 root 密码（最后务必点 Execute）。

### 步骤

**① 建库**

```sql
CREATE DATABASE sf_project CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

**② 启动后端**（`software_project_design/` 目录下）

```cmd
set "DB_DSN=root:你的MySQL密码@tcp(localhost:3306)/sf_project?charset=utf8&parseTime=True&loc=Local"
go run main.go
```

成功标志是这两行**同时**出现：

```json
{"level":"info","msg":"MySQL DSN source","source":"env:DB_DSN"}
[GIN-debug] Listening and serving HTTP on localhost:8082
```

> 若 `source` 是 `built-in default`，说明 `DB_DSN` 没传进去，会按无密码的本机 root 连接；你的 root 有密码时必然 `Access denied`。
>
> 空库首次启动时后端会自动建表（GORM AutoMigrate）；表已存在时自动跳过，避免改写 `database/schema.sql` 建出的约束。可用 `DB_AUTO_MIGRATE=true/false` 强制开关。
>
> **可选（报告评测用）**：不走 AutoMigrate，而是先执行仓库根目录的 `database/schema.sql` + `database/indexes.sql` 建表（含外键/CHECK/复合索引），或直接用 `scripts/seed_data.py --db sf_project --scale small` 一步建表并造约 1 万行数据（同样包含下面三个演示账号），详见根目录 README。

**③ 导入种子数据**

```cmd
"C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe" -u root -p --default-character-set=utf8mb4 sf_project < seed.sql
```

应打印 `user 3 / category 3 / jackfruit 5 / orders 3 / review 3 / notify 1`。

**④ 前端使用真实模式**

确认 `jackfruit-frontend-V3/.env.development` 里是 `VITE_USE_MOCK=false`（当前默认值），然后 `npm run dev`。现在读写的就是真实 MySQL 了。

### 常见报错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Access denied for user 'root'` | `DB_DSN` 没生效 | 看日志 `MySQL DSN source` 应为 `env:DB_DSN`；是 `built-in default` 就是没传进去 |
| `go: command not found` | 装完 Go 没重开终端 | 关掉所有终端重开 |
| `go run` 卡在 `downloading` | 没设模块代理 | `go env -w GOPROXY=https://goproxy.cn,direct` |
| `Unknown database 'sf_project'` | 没建库 | 回到第 ① 步 |
| `connect: connection refused`(3306) | MySQL 服务没起 | `net start MySQL84`（管理员终端） |
| 时间显示 `0001-01-01` | DSN 少了 `parseTime=True` | 检查连接串 |
| 前端请求全部 404 | 没切 `VITE_USE_MOCK=false` | 改环境变量并重启 dev |

## 五、给 merge 的建议

1. **合并风险低**。新前端是独立目录，旧前端未动；后端只改了 `global.go` 的连接串外置（不设环境变量时默认连本机无密码 root）。
2. **建议的合并顺序**：本分支可直接合入。`global.go` 的改动建议保留——它让任何人 clone 后不用改源码就能连自己的数据库。
3. **旧前端建议保留**，不要删。它在重构期是对照基准；且新前端目前是 Mock 可用、真后端可选，旧前端仍可作为兜底。
4. **`jackfruit-frontend-V3/node_modules` 已在 `.gitignore` 里**，不会进版本库。clone 后跑 `npm install` 即可。

## 六、已知限制（非 bug，是后端现状）

这些行为来自后端实现，新前端如实呈现，没有额外掩盖：

- **无真正鉴权**：后端没有角色字段、没有 token。前端的「管理员/普通会员」区分来自 `src/config/permissions.ts` 的用户名白名单，是界面层的可见性控制，不是安全边界。普通账号直接调接口仍可调通。
- **订单不带买家信息**：`OrderUserId` 的 json tag 是 `json:"-"`，接口不返回该字段，前端无法关联到具体会员，订单页只能显示商品信息。
- **`storage=0` / `price=0` 视为不修改**：后端更新商品时把 0 当作「不更新此字段」。
- **密码明文**：数据库存明文，登录密码走 query string。这是后端现状，新前端未做改动。
